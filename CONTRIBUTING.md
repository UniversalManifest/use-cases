# Contributing

This repository holds applied write-ups and figures that walk the Universal Manifest specification through concrete scenarios. The specification itself is in [UniversalManifest/universal-manifest](https://github.com/UniversalManifest/universal-manifest). Raise specification changes there, not here.

## Submitting a use case

Open an issue with the **Use case** form. The form asks for:

- an **identifier**: short, lowercase words joined by hyphens, such as `venue-entry-age-check`. It becomes the use case's section anchor, so it must be unique and should not change after acceptance;
- the **submitter**: your name or organization, as it should be credited;
- the scenario, the parties involved, and which parts of the specification it exercises.

## Review process

1. A maintainer of this repository reads the issue and checks that the identifier is unique and the form is complete.
2. The maintainer either asks questions in the issue or labels it accepted for drafting.
3. An accepted use case is written up in a pull request that cites the issue and uses the identifier as its anchor.
4. The maintainers review the pull request. A maintainer merges it, or closes it with the reason stated in the pull request.
5. A merged use case is accepted. A change to an accepted use case follows the same steps.

The maintainers of this repository decide at each step. A use case describes how the specification is used. It does not change the specification.
